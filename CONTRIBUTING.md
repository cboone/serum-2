# Contributing to serum-2

Thank you for your interest in contributing to serum-2.

Please note that this project has a [Code of Conduct](CODE_OF_CONDUCT.md). By participating, you are expected to uphold it.

This project is not affiliated with, endorsed by, or sponsored by Xfer Records. Serum is a trademark of Xfer Records, named here only to describe compatibility.

## Reporting Issues

- **Bug reports and feature requests:** Use the [issue tracker](https://github.com/cboone/serum-2/issues). For a format problem, say which Serum version saved the file.
- **Security vulnerabilities:** See [SECURITY.md](.github/SECURITY.md)

## Development Setup

### Requirements

- [`uv`](https://docs.astral.sh/uv/) (the only hard requirement to _run_ the tools)
- [`scrut`](https://github.com/facebookincubator/scrut) to run the CLI tests
- Node and `npm` to run the text checks, which come from this repository's `package-lock.json`

There is no Python dependency install step. Every tool is a standalone script carrying [PEP 723](https://peps.python.org/pep-0723/) inline metadata with exact pins and a hash-checked lockfile (`tools/*.py.lock`), so `uv` resolves each script's dependencies on first run.

The `package.json` at the root does not make this a JavaScript project. It exists only to pin `markdownlint-cli2`, `prettier` and `cspell`, so that `make text-lint` and CI run identical versions. `make text-lint` and `make text-fix` install them on first use.

### Getting Started

```bash
# Clone the repository
git clone https://github.com/cboone/serum-2.git
cd serum-2

# Run a tool. Nothing to install first.
tools/serumfile.py verify tests/scrut/fixtures/serum/Presets/Example.SerumPreset

# Run every check: Ruff, text checks and the CLI tests
make check
```

`make help` lists every target.

## Example Files and Fixtures

- Every example or fixture file is dedicated to the public domain under CC0 ([LICENSE-ASSETS](LICENSE-ASSETS)), and must be either generated by a script in this repository or plainly non-creative.
- Never contribute presets, curves or wavetables copied from Serum's factory content or from third-party packs, including files you have modified.
- Fixtures are generated. Change `tests/scrut/fixtures/make_fixtures.py` and rerun it instead of editing fixture files:

  ```bash
  PYTHONPATH=tools uv run --script tests/scrut/fixtures/make_fixtures.py tests/scrut/fixtures/serum
  ```

- The wavetables in `serum/Tables/` are generated too. Regenerate them with `tools/make_sweep.py serum/Tables`.

## Format Claims

When you document something about the file format, say how you know it: confirmed against files saved by Serum (name the version), stated in a manual, or inferred. Do not present inferred structure as established.

## Code Style

- Run `make lint` and `make fmt` before committing. `make fmt-fix` applies both.
- Run `make text-lint` for Markdown, formatting and spelling. Add project words to `cspell-words.txt`.

Do not add a `pyproject.toml` or otherwise convert the repository into an installable package. The standalone-script layout is deliberate.

## Commit Messages

Use [Conventional Commits](https://www.conventionalcommits.org/) format:

```text
<type>: <description>
```

**Types:**

- `feat`: new feature
- `fix`: bug fix
- `docs`: documentation changes
- `refactor`: code refactoring (no functional change)
- `test`: adding or updating tests
- `build`: build system or dependency changes
- `ci`: CI configuration changes
- `chore`: maintenance tasks
- `style`: formatting only, no functional change

**Examples:**

```text
feat: add a subcommand listing a preset's macros
fix: exit non-zero from verify when a check fails
docs: record which source IDs are confirmed
```

## Pull Request Process

1. Fork the repository
1. Create a feature branch
1. Make your changes
1. Ensure every check passes: `make check`
1. Submit a pull request

### Branch Naming

Use descriptive branch names with a type prefix:

- `feature/*`: new features
- `fix/*`: bug fixes
- `docs/*`: documentation changes
- `refactor/*`: code refactoring
- `test/*`: test additions or fixes
- `chore/*`: maintenance tasks
